基于**历史形态相似度匹配 + 多维融合 + Walk-Forward 自适应 ML + 量化回测**的 A 股短线统计研究工具。

> **v6.0（2026-09-16）**：三档组合策略引擎（`stock_gui.py` 内嵌 `tier_*`，稳健/均衡/激进）
> 进入**生产端**（GUI 工具菜单 / CLI `--tiers`、`--tiers-backtest`），研究脚本与生产共用一套实现；
> 全部 **T-1 信号 → T 日收盘成交**、滑点/佣金/印花税/过户费/整手/涨跌停/退市了结完备；
> 修复 v5「激进双引擎」同日信号同日成交的前视 bug（修复后不再跑赢创业板指）；
> 全库补齐 `adjust` 现价缩放系数（5849/5850 只，低价分位与整手成本口径不再失真）。
> **个人研究项目，全部输出仅供历史统计参考，不构成投资建议。**

## 一、三档策略（v6.0 定版）

公共口径：股票池为**全A**（沪深主板/创业板/科创板，剔除北交所/指数/ETF）；
时点过滤 = 价 >1 元、上市 ≥250 个交易日、20 日均成交额 ≥3000 万元；
信号只用 **T-1 及以前**的数据，**T 日收盘成交**；持有至下一调仓日，若股票跌出目标则次日尝试卖出。

| 档位 | 基准 | 选股 | 调仓 | 择时闸门 |
|---|---|---|---|---|
| **稳健** | 上证指数 | 全A：20 日动量 + 20 日低波 合成排名 Top20 | 每 20 日 | 上证 MA20（收盘在均线上才持仓） |
| **均衡** | 上证指数 | 同上 Top20 | 每 10 日 | 上证 MA20 |
| **激进** | 创业板指 | 创业板：60 日 β（对创业板指）最高 Top5 | 每 10 日 | 创业板指 MA60 |

- 合成排名：`rank(20日收益) + (1 − rank(20日波动))`，横截面百分位，等权两项；
- 闸门关闭（T-1 收盘 < MA）→ 调仓日清仓持现金，恢复后重新建仓；
- 调仓相位：资金分成 `reb` 份、错开相位同时运行后平均（tranche averaging），
  消除「起始日/调仓日恰好撞上行情」的运气；报告同时给出单相位年化区间。

> **参数选择协议**：结构（因子、top、调仓、闸门）在训练段 **2022-09 ~ 2024-12** 内完成选型；
> `val`（2025-09 ~ 2026-09）与 `bull`（2025-03 ~ 2026-09）仅用于报告。
> 诚实声明：探索过程中确实看过后段数据（本项目历史遗留口径污染无法完全消除），
> 因此下面同时给出全期、样本外、逐年三张表与相位离散度，请以后两者为主要依据。

### 1.1 策略原理

**为什么是「动量 + 低波」而不是模型打分？** 2026-09-13 的审计（`回测复核报告_20260913.md`）
证明逐股选型/ML 横截面打分在样本外归零（选择偏差 + 训练 IC 0.6 vs 测试 0.016）。
价格/量能类有效信息主要来自两类稳健风格：**趋势延续**与**低波动异象**，因此三档都只做
「横截面排序 + 趋势闸门」，不做参数寻优式拟合。

1. **合成排名（稳健/均衡）**：`score = rank(20日收益) + (1 − rank(20日波动))`。
   动量项捕捉资金持续流入（趋势），低波项压低高波动/高换手个股的崩盘概率；
   两项都取横截面百分位再等权，天然回避量纲与极端值问题。
2. **β 选股（激进）**：以 60 日对创业板指回归 β 排序，取最高 5 只。逻辑是
   「趋势在时用高 β 放大指数上行」——创业板 β 高的名字在指数上行段弹性更大；
   集中 5 只意味着高波动，所以必须配合慢闸门。
3. **趋势闸门（择时）**：`T-1 收盘 > MA(N)` 才允许持仓，否则调仓日清仓持现金。
   上证用 MA20（快，匹配 10~20 日调仓），创业板用 MA60（慢，避免高波动指数被
   短期噪音反复打脸；2024-2025 实测 MA20 会被洗到负收益）。闸门的作用是**避开
   系统性下跌段**，代价是单边强趋势初期会晚入场（逐年表里牛市跑输主因）。
4. **调仓相位平均（tranche）**：把资金分 `reb` 份、相位错开同时运行后平均。
   单一调仓日的结果对「起始日运气」极其敏感（实测同一策略不同相位可差 50pp+），
   相位平均报告的是策略的期望表现而非某一次巧合。
5. **成交与费用**：T-1 收盘决策 → T 日收盘成交；滑点 0.1%/边、佣金万 2.5（最低 5 元）、
   印花税千 1（卖出）、过户费；100 股整手、涨停不买、跌停次日再卖、停牌顺延、
   退市/长停 20 日后按最后收盘价了结。所有过滤（价 >1、上市 ≥250 日、20 日均额
   ≥3000 万）都用 T-1 数据，**不存在未来信息**。
6. **生产端口径差异**：GUI/CLI 的「当前目标持仓」额外剔除当前 ST/退市风险名称
   （历史回测无时点 ST 数据，故回测不含该过滤）；其余规则完全一致。

| 检查 | 结果 |

## 三、复现与生产端

### 3.1 研究复现

```bash
# 0) 刷新 adjust 现价系数（可选，仓库内数据库已含）
python sync_adjust.py

# 1) 三档全期 / 样本外 / 强势段
python backtest_tiers.py --tier all --segment full
python backtest_tiers.py --tier all --segment val
python backtest_tiers.py --tier all --segment bull

# 2) 逐年
python backtest_tiers.py --tier all --segment yearly

# 3) 参数敏感性（示例：激进换闸门/持仓数）
python backtest_tiers.py --tier 激进 --segment full --gate-ma 20
python backtest_tiers.py --tier 激进 --segment full --top 7
```

> `backtest_tiers.py` 只是命令行封装；**引擎实现内嵌在 `stock_gui.py`（`tier_*` 函数）**，
> `stock_predict.py` 由 `build_cli.py` 从 `stock_gui.py` 自动抽取生成，三端共用一套实现，
> 不会出现研究/生产口径分叉。

### 3.2 生产端（GUI / CLI）

**GUI**（`python stock_gui.py`）→ 工具菜单：

- `v6.0 三档组合（当前目标持仓）`：按最新可用交易日给出三档目标持仓、
  闸门状态（在场/空仓）、每只票的建议手数与金额（默认 10 万资金）、分数/波动/β、
  参考止损；ST/退市风险名自动剔除，买不起（一手 > 单仓预算）的票自动跳过；
- `v6.0 三档回测（全期，相位平均）`：后台跑全期回测并弹摘要（约 1~2 分钟）；
- `v6.0 荐股收益回测（按风险偏好）`：逐笔荐股统计（笔数/平均/胜率/盈亏比/右尾）。

**GUI 每日荐股窗口**（主界面「荐股」按钮）：顶部新增风险偏好下拉框——
选 `稳健/均衡/激进` 时列表来自 v6.0 三档引擎（含建议手数/金额/参考止损；
闸门关闭会显示「空仓等待」），选 `综合(旧评分)` 保留旧的多维评分列表。
双击任意推荐行可直接切到该股分析。

**CLI**：

```bash
python stock_predict.py --tiers                  # 三档当前目标持仓（含参考止损）
python stock_predict.py --tiers --tier 激进       # 只看某一档
python stock_predict.py --tiers-backtest          # 全期组合回测摘要
python stock_predict.py --picks-backtest          # 荐股收益回测（逐笔，全期）
python stock_predict.py --picks-backtest --picks-seg val   # 指定区间
```

依赖：`numpy + scikit-learn + lightgbm`（基础功能纯标准库可跑，三档引擎需要 numpy）。

## 五、数据

- 行情源：腾讯 → 东方财富多源容灾；本地 SQLite `stock_cache.db`。
- **复权口径修复（2026-09-16/17，重要）**：审计发现并修复三处数据问题：
  1. **库内混用复权口径**：此前约九成代码实际存的是**不复权/前复权价**（如白云机场 7.74），
     而非文档口径的后复权 hfq（贵州茅台等少数为 hfq）。已用 `data_clean.py --all-adj`
     全库迁移为腾讯**后复权**（5449/5495 只成功，约 1600 根/只；40 只问题股因 hfq 序列
     毛刺拒绝迁移、保持原数据；北交所免费源无深历史，仅作展示）。收益率口径因此修正
     （此前不复权序列含分红除权跳空）。
  2. **`adjust.k` 配对错位**：旧实现用「实时价 ÷ 库内最后一根」配对，日K落后数日时
     会把整段历史价格按「最新价/落后日价」缩放错（京东方A 昨收一度显示成今日价）。
     现改为**同一交易日** raw/库内收盘配对，k 取多日比值中位数；末根与中位明显不一致
     （腾讯偶发复权毛刺）时自动重拉修复，拉不到一致值则删除该根。另修复了
     `_fetch_tencent`/`_fetch_tx_kline` **不复权日K URL 缺少尾逗号**导致返回空的问题。
  3. **收盘后当日K入库**：`last_completed_td` 改为收盘后（≥15:05）以当天为新鲜度基准，
     今日已定型日K可直接入库（此前永远延迟到次日）。
- `adjust(code, k)` 存 `k = 同一交易日不复权收盘 / 库内收盘`，读取层按 `库内价 × k`
  还原「乘法前复权（≈现价）」；`sync_adjust.py` 可批量刷新并修复末根毛刺。
- 清洗：结构异常删除、整只重拉、退市登记、停牌报告；`data_clean.py` 仅报告，`--fix` 才改库。
- 客户端数据包（含修复后的 `stock_cache.db`，258MB）与研究产物见 Release `v6.0`：
  `stock-analyzer-client-20260917.zip`（程序 + 数据库）、`research_v6.0.zip`（回测 JSON 与报告）；
  旧缓存包（v4.0-cache，复权口径未修复）不再推荐：

## 七、已知局限

1. 数据仅覆盖 2022-09 以来（指数/多数个股），全期不足 4 年，**不能覆盖完整牛熊**；
2. 激进档集中持仓 5 只、年化波动 >40%，单年可能大幅跑输（2024/2025 已发生）；
3. MA 闸门在单边强趋势中会滞后（2024-2025 跑输的直接原因之一）；
4. 整手约束下小资金（<10 万）无法完全复制 Top20 组合，实际需按资金量缩减股票数；
5. 未建模冲击成本/一字板，停牌与退市按最后收盘价了结，可能高估极端情形下的可回收价值；
6. 参数选型虽在训练段完成，但样本短、探索次数多，**仍存在选择偏差**，请以逐年表与相位区间为准。
